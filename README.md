# FINNI 🦕

### Интерактивное приложение для обучения детей финансовой грамотности

**FINNI** — мобильное приложение для детей 7–11 лет, которое знакомит с основами финансовой грамотности через взаимодействие с виртуальным питомцем-динозавром. Пользователь выполняет задания, получает игровую валюту, заботится о питомце, планирует расходы и формирует накопления для достижения целей.

Приложение разработано на Flutter для Android. Основной образовательный принцип — освоение финансовых понятий через игровые ситуации, наглядную обратную связь и самостоятельные решения.

## 2. Возможности приложения

Основные игровые и образовательные функции:

* **Виртуальный питомец.** Пользователь заботится о динозавре и следит за его состоянием.
* **Задания.** Выполнение игровых задач помогает знакомиться с финансовыми понятиями и получать вознаграждение.
* **Игровая экономика.** Монеты используются во внутриигровых сценариях.
* **Бюджетирование.** Пользователь распределяет доступные средства по категориям бюджета.
* **Накопления и цели.** Пользователь может планировать накопления и отслеживать продвижение к выбранной цели.
* **Магазин.** Игровая валюта используется для предусмотренных приложением покупок.
* **Игровой прогресс.** Уровень и состояние питомца обеспечивают обратную связь о действиях пользователя.

Приложение предназначено для обучения, а не для совершения реальных денежных операций. Игровые монеты не являются денежными средствами.

## 3. Образовательная ценность

FINNI знакомит пользователя со следующими понятиями:

* ограниченность доступных ресурсов;
* различие между расходами и накоплениями;
* распределение бюджета;
* постановка финансовой цели;
* планирование покупок;
* связь между выполнением задач и получением вознаграждения.

Игровой формат позволяет отрабатывать решения в виртуальной среде без риска потерять реальные деньги.

## 4. Состав репозитория

Основные каталоги и файлы проекта:

* `lib/` — исходный код приложения на Dart.
* `lib/main.dart` — точка входа и основной экран приложения.
* `lib/services/` — сервисы и управление игровым состоянием.
* `lib/screens/` — экраны и пользовательские сценарии.
* `assets/` — изображения, иконки, аудиофайлы и другие ресурсы приложения, если они предусмотрены конфигурацией проекта.
* `android/` — конфигурация Android-приложения.
* `windows/` — конфигурация запуска приложения под Windows.
* `pubspec.yaml` — зависимости, версия приложения и настройки ресурсов Flutter.
* `pubspec.lock` — зафиксированные версии зависимостей Dart/Flutter.
* `analysis_options.yaml` — настройки статического анализа Dart, если файл присутствует в репозитории.

Служебные каталоги сборки, кэш зависимостей и локальные настройки среды разработки не являются частью исходного кода приложения.

## 6. Быстрый запуск

### 6.1. Получение исходного кода

```bash
git clone https://github.com/RANIK-code-jpg/FINNI_APP.git
cd FINNI_APP
```

### 6.2. Проверка окружения

```bash
flutter --version
flutter doctor
```

При необходимости установите недостающие компоненты Android SDK и примите необходимые лицензии:

```bash
flutter doctor --android-licenses
```

### 6.3. Установка зависимостей

```bash
flutter pub get
```

### 6.4. Запуск приложения

Подключите Android-устройство с включённой отладкой по USB или запустите эмулятор.

Проверьте доступные устройства:

```bash
flutter devices
```

Запустите приложение:

```bash
flutter run
```

Для запуска на Windows при наличии соответствующей конфигурации:

```bash
flutter run -d windows
```

## 7. Сборка релизного APK

### 7.1. Подготовка

Перейдите в корневую папку проекта и установите зависимости:

```bash
flutter pub get
```

Проверьте конфигурацию Android-приложения:

* уникальность `applicationId`;
* версию приложения и номер сборки;
* конфигурацию подписи релизной сборки;
* наличие необходимых ресурсов;
* совместимость SDK и Gradle.

### 7.2. Подпись приложения

Релизная сборка для распространения должна быть подписана. Для этого необходимо настроить релизный ключ подписи и конфигурацию Gradle в соответствии с документацией Android.

**Не размещайте в репозитории закрытый ключ подписи, пароли, токены или файл с секретами.** Храните их вне репозитория и используйте локальную конфигурацию или защищённые секреты CI/CD.

Перед публикацией проверьте, что APK подписан ожидаемым сертификатом. Сам факт успешного выполнения команды сборки не подтверждает, что использован правильный релизный ключ.

### 7.3. Сборка

Выполните:

```bash
flutter build apk --release
```

После успешного завершения сборки файл обычно располагается по пути:

```text
build/app/outputs/flutter-apk/app-release.apk
```

### 7.4. Проверка APK

Перед распространением:

1. Убедитесь, что APK существует и имеет ненулевой размер.
2. Проверьте подпись и сертификат APK.
3. Установите приложение на Android-устройство без Android Studio.
4. Проверьте запуск, навигацию, игровые сценарии и сохранение данных.
5. Зафиксируйте версию приложения, номер сборки и результат тестирования.
6. Опубликуйте проверенный APK в GitHub Releases.

Команда установки через ADB, если Android SDK Platform-Tools установлены:

```bash
adb install build/app/outputs/flutter-apk/app-release.apk
```

## 8. Архитектура и данные

Приложение организовано по экранам и сервисам.

* **Точка входа:** `lib/main.dart`.
* **Экраны:** каталог `lib/screens/` содержит пользовательские разделы приложения.
* **Игровое состояние:** сервисы в `lib/services/` управляют состоянием и игровыми параметрами.
* **Ресурсы:** каталог `assets/` используется для статических материалов, подключённых в конфигурации Flutter.
* **Платформенная конфигурация:** каталог `android/` содержит Android-специфичные настройки.

Состав экранов и фактическое распределение логики следует сверять с актуальным исходным кодом.

Приложение предусматривает работу без обязательной регистрации пользователя. Фактический механизм хранения и восстановления игрового состояния определяется реализацией сервисов и подключённых зависимостей.

## 9. Тестирование

Перед выпуском необходимо проверить следующие сценарии:

* установка и первый запуск APK на Android;
* открытие основных экранов;
* выполнение заданий и начисление игровых монет;
* корректность баланса и покупок;
* распределение бюджета и работа накоплений;
* изменение игрового прогресса;
* корректность отображения на портретном экране;
* поведение приложения при повторном запуске;
* воспроизведение звука и фоновой музыки;
* отсутствие критических ошибок при навигации.

Результаты фактически выполненных тестов следует указать в финальной версии документации. Непроверенные сценарии нельзя отмечать как успешно пройденные.

## 10. Ограничения

* Приложение предназначено для обучения в игровой форме и не заменяет полноценный курс финансовой грамотности.
* Игровая валюта не имеет реальной денежной стоимости.
* Поведение и доступность отдельных функций зависят от текущей реализации приложения.
* Совместимость с конкретными версиями Android и корректность работы на разных устройствах необходимо подтверждать тестированием.
* Возможные ограничения звукового воспроизведения, сохранения состояния и других функций должны быть зафиксированы по результатам проверки финальной сборки.
